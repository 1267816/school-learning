# 实验报错日志

## 日志一

### 一、 基本信息

- **源文件名**：5-1.2.c
- **开发环境**：Embarcadero Dev-C++ 6.3
- **编译器版本**：TDM-GCC 9.2.0 64-bit Release
- **代码功能**：计算并输出斐波那契（Fibonacci）数列的前 12 项，要求每行输出 4 个数。

### 二、 问题现象

程序编译通过且正常运行，但输出结果**没有按照预期换行**。12 个数字全部挤在了同一行输出。

### 三、 错误代码（问题片段）

在输出循环中，控制换行的 `if` 条件被写成了：

```c
if (i%4+1 == 0)
```

### 四、 错误原因分析

1. **优先级问题**：C 语言中，取模运算符 `%` 的优先级高于加法运算符 `+`。因此 `i%4+1 == 0` 实际等价于 `(i % 4) + 1 == 0`。
2. **逻辑错误**：因为 `i` 从 0 开始递增，`i % 4` 的结果只能是 `0, 1, 2, 3`，那么 `(i % 4) + 1` 的结果最小也是 1（即 1, 2, 3, 4）。
3. **结果**：该表达式的结果**永远不可能等于 0**，因此 `if` 语句内部的 `printf("\n");` 永远无法执行，导致无法换行。
4. **正确逻辑**：想要实现每 4 个数换行，应该在打印第 4、8、12 个数时换行（即 `i = 3, 7, 11` 时）。此时 `(i + 1) % 4 == 0` 或者 `i % 4 == 3` 才是正确的条件。

### 五、 修正方案

将 `if` 语句的条件修改为：

```c
if ((i+1)%4 == 0)
```

## 日志二

### 一、 基本信息

- **源文件名**：5-2.c
- **开发环境**：Embarcadero Dev-C++ 6.3
- **编译器版本**：TDM-GCC 9.2.0 64-bit Release
- **代码功能**：对二维数组（3行4列矩阵）进行遍历处理，要求找出每行的**最小元素**，并与该行第一个元素交换位置。

### 二、 问题现象

1. **编译失败**：程序无法生成可执行文件。底部编译日志报错信息如下：
   `[Error] 'k' undeclared (first use in this function)` （发生在第 31 行）。
2. **逻辑错误**：即使解决了编译报错，程序也无法正确找出每行的最小元素（反而找出了最大元素）。

### 三、 错误代码（问题片段）

在二维数组的行遍历过程中，变量 `k` 的定义与使用位置，以及比较条件如下：

```c
    for (i=0; i<3; i++) {
        for (j=0; j<4; j++) {
            int k=0;          // 第26行：变量 k 在此处声明
            if (a[i][j]>a[i][k]) { // 第27行：比较条件错误
                k=j;
            }
        }                     // 第30行：内层循环结束
        swap(&a[i][0],&a[i][k]); // 第31行：报错位置，找不到变量 k
    }
```

### 四、 错误原因分析

1. **作用域越界（导致编译报错）**：第 26 行的 `int k=0;` 是定义在内层 `for (j=0; j<4; j++)` 循环体内部的**局部变量**。当内层循环执行完毕（遇到第 30 行的右大括号 `}`）时，变量 `k` 的内存空间就被释放了，其生命周期结束。到了第 31 行执行 `swap` 交换函数时，编译器已经无法识别 `k` 是什么，因此报出 `'k' undeclared`（k 未声明）的错误。
2. **初始化位置错误（导致逻辑错误）**：把 `int k=0;` 放在 `j` 循环内部，会导致每次 `j` 增加时 `k` 都被重新初始化为 0，这无法正确记录整行最小值的下标。
3. **比较条件写反（导致功能不符）**：题目要求找“每行**最小**元素”，而原代码使用了 `>` 运算符（`a[i][j] > a[i][k]`）。这个逻辑实际上是在不断寻找比当前记录值**更大**的元素，最终找到的是该行的**最大值**。

### 五、 修正方案

1. **解决编译报错与初始化**：需要扩大变量 `k` 的作用域。应当将 `int k=0;` 的声明**移到内层 `for (j...)` 循环的外面**，但要保留在外层 `for (i...)` 循环的里面，确保每次处理新的一行时，`k` 都能被正确重置。
2. **修正比较逻辑**：将找最大值的条件 `>` 改为找最小值的条件 `<`，即 `if (a[i][j] < a[i][k])`。

## 日志三

### 一、 基本信息

- **源文件名**：5-4.c
- **开发环境**：Embarcadero Dev-C++ 6.3
- **编译器版本**：TDM-GCC 9.2.0 64-bit Release
- **代码功能**：在一个包含 15 个元素的有序数组中，使用二分查找法（折半查找）寻找用户输入的指定数字，并输出其位置或提示不在表中。

### 二、 问题现象

程序编译可以通过（无语法错误），但运行后会卡死（无响应），或者在找到目标数字后程序仍然无法结束，陷入**死循环**。

### 三、 错误代码（问题片段）

在二分查找的 `while` 循环中，边界更新和找到目标后的处理逻辑如下：

```c
        else if (n>a[mid]) {
            left=mid;
        } else {
            right=mid;
        }
```

### 四、 错误原因分析

1. **边界更新错误导致死循环**：在二分查找中，如果目标值大于中间值（`n > a[mid]`），说明目标在右半区，此时应将 `left` 更新为 `mid + 1`；如果目标值小于中间值，说明目标在左半区，应将 `right` 更新为 `mid - 1`。
2. **区间未缩小**：原代码中直接写成了 `left = mid;` 和 `right = mid;`。如果 `n > a[mid]` 执行 `left = mid;`，下一次循环时计算出的 `mid` 依然是当前值，搜索区间根本没有缩小，从而造成无限循环。
3. **找到目标后未退出循环**：在 `if (n == a[mid])` 分支中，虽然记录了 `isfound = 1` 和 `result = mid + 1`，但**没有使用 `break;` 跳出循环**，这会导致程序继续往下执行，从而引发不必要的错误或死循环。

### 五、 修正方案

1. 修改边界收缩逻辑，避免死循环：将 `left = mid;` 改为 `left = mid + 1;`，将 `right = mid;` 改为 `right = mid - 1;`。
2. 找到目标后立即跳出查找：在 `if (n == a[mid])` 的内部，在 `result=mid+1;` 之后添加 `break;`。
