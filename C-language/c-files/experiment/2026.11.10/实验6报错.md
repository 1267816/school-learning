# 报错记录及修改方法

1. **报错内容：**

```text
In function 'fun':
[Warning] type of 'm' defaults to 'int' [-Wimplicit-int]
```

**错误原因：**
在定义 `fun` 函数时，形参 `m` 未指定数据类型。编译器默认将其视为 `int` 类型，从而触发隐式声明警告。

**修改方法：**
在函数定义处，为形参 `m` 显式加上 `int` 类型声明。

```c
/* 修改前 */
double fun(m) 

/* 修改后 */
double fun(int m)
```

## 运行结果分析与理解

**现象描述：**
预期输出结果为 `7 7 7`，但实际运行结果为 `7 8 9`。

**原因分析（为什么会是 7 8 9 而不是 7 7 7）：**
产生预期偏差的核心原因在于函数 `f` 中使用了 **`static` 关键字**修饰局部变量 `c`。

* **关于变量 `b`（自动局部变量）：**
    每次调用 `f` 函数时，`b` 都会被重新创建并初始化为 `0`，因此每次 `b=b+1` 后，`b` 的值始终为 `1`。
* **关于变量 `c`（静态局部变量）：**
    `static int c=3;` 这条初始化语句在整个程序运行期间**只会执行一次**（即第一次调用 `f` 函数时）。之后的每次函数调用，`c` 都会保留上一次调用结束时的值，且不会被重新初始化。

**详细调用过程解析：**

1. **第一次循环（`i=0`）：**
    传入 `a=2`，`b` 初始化为 `0`，`c` 初始化为 `3`。
    执行 `b=b+1` 得 `b=1`；执行 `c=c+1` 得 `c=4`。
    返回 `a+b+c = 2+1+4 = 7`。此时 `c` 的值被保留为 `4`。
2. **第二次循环（`i=1`）：**
    传入 `a=2`，`b` 重新初始化为 `0`，跳过 `c` 的初始化（`c` 保留上次的值 `4`）。
    执行 `b=b+1` 得 `b=1`；执行 `c=c+1` 得 `c=4+1=5`。
    返回 `a+b+c = 2+1+5 = 8`。此时 `c` 的值被保留为 `5`。
3. **第三次循环（`i=2`）：**
    传入 `a=2`，`b` 重新初始化为 `0`，跳过 `c` 的初始化（`c` 保留上次的值 `5`）。
    执行 `b=b+1` 得 `b=1`；执行 `c=c+1` 得 `c=5+1=6`。
    返回 `a+b+c = 2+1+6 = 9`。此时 `c` 的值被保留为 `6`。

**结论：**
因为使用了 `static` 关键字，`c` 的值具有“记忆”功能，每次调用会递增。如果想输出 `7 7 7`，需要去掉 `c` 前面的 `static` 关键字，使其变为普通的局部变量。

# 报错记录及修改方法

1. **报错内容：**
输入测试数据 `1` 时，程序预期应输出 `no`（因为数学上1既不是素数也不是合数），但实际输出结果为 `yes`。

**错误原因：**
在 `isPrime` 函数中，没有对 `x = 1` 这种特殊情况进行处理。当传入 `x = 1` 时，`for` 循环条件 `i*i <= x`（即 `4 <= 1`）不成立，循环体根本不会执行。此时标志变量 `ret` 保持初始值 `1`，导致函数错误地将 `1` 判定为素数并返回 `1`。

**修改方法：**
在 `isPrime` 函数返回 `ret` 之前，增加对 `x == 1` 的判断，若输入为 1，则手动将 `ret` 置为 `0`。

```c
/* 修改前 */
int ret=1;
for (int i=2; i*i<=x; i++) {
    if (x%i==0) {
        ret=0;
        break;
    }
}
return ret;

/* 修改后 */
int ret=1;
for (int i=2; i*i<=x; i++) {
    if (x%i==0) {
        ret=0;
        break;
    }
}
if (x==1) {
    ret=0;
}
return ret;

1. **报错内容：**
```text
[Error] unknown type name 'length'
[Error] expected declaration specifiers or '...' before '*' token
```

**错误原因：**
在定义 `f` 函数的参数列表时，形参 `length` 没有指定数据类型。编译器将其误认为是未知的类型名，从而导致后续指针参数的声明解析失败，产生连锁报错。

**修改方法：**
在形参 `length` 前显式加上 `int` 类型声明。

```c
/* 修改前 */
int f(char* a, length, int *pletter, int *pnum, int *pspace, int *pother) {

/* 修改后 */
int f(char* a, int length, int *pletter, int *pnum, int *pspace, int *pother) {
```

1. **报错内容：**

```text
[Note] expected 'const char *' but argument is of type 'char **'
[Error] expected expression before ']' token
```

**错误原因：**

1. 数组定义错误：第20行 `char* a[101]={0};` 定义了一个指针数组。当把 `a` 传给 `strlen` 函数时，它退化为 `char **`（指向指针的指针），与 `strlen` 要求的 `const char *` 类型不匹配。
2. 传参语法错误：第30行调用 `f` 函数时写成了 `f(a[], ...)`。在C语言中，传递整个数组时只能写数组名，不能在数组名后加方括号，导致编译器无法解析。

**修改方法：**
将第20行的指针数组修改为普通的字符数组，并将第30行的传参改为直接传数组名 `a`。

```c
/* 修改前 */
char* a[101]={0};                             // 第20行
f(a[], length, &letter, &num, &space, &other); // 第30行

/* 修改后 */
char a[101]={0};                             // 第20行
f(a, length, &letter, &num, &space, &other); // 第30行
```

1. **报错内容：**

```text
[Warning] implicit declaration of function 'strlen' [-Wimplicit-function-declaration]
[Warning] incompatible implicit declaration of built-in function 'strlen'
```

**错误原因：**
在代码第27行使用了计算字符串长度的 `strlen` 函数，但没有在文件开头包含对应的头文件。导致编译器找不到该函数的声明，只能进行隐式声明，从而产生警告。

**修改方法：**
在源文件顶部的 `#include` 区域添加字符串处理头文件 `<string.h>`。

```c
/* 修改前 */
#include <stdio.h>

/* 修改后 */
#include <stdio.h>
#include <string.h>
```

1. **报错内容：**
编译无报错，但运行时输入 `1234` 等测试数据后，输出的统计结果全部为 `0`（`letter=0, num=0, space=0, other=0`）。

**错误原因：**
在C语言中，后缀自增运算符 `++` 的优先级高于解引用运算符 `*`。
代码中第9、11、13、15行写成了 `*pnum++;` 等语句，它实际上等价于 `*(pnum++);`。
这会导致两个错误结果：

1. 仅仅是让指针变量 `pnum` 自身的内存地址向后移动了一个单位，并没有改变它所指向的 `main` 函数中的变量值。
2. `main` 函数中的 `num` 等变量始终保持初始值 `0`，未被累加，因此最终输出全为 `0`。

**修改方法：**
需要对指针解引用后的值进行自增，必须加上括号，先解引用再自增。

```c
/* 修改前 */
*pletter++;
*pnum++;
*pspace++;
*pother++;

/* 修改后 */
(*pletter)++;
(*pnum)++;
(*pspace)++;
(*pother)++;
```

1. **报错内容：**

```text
[Error] subscripted value is neither array nor pointer
```

**错误原因：**
在 `max` 函数定义中，形参 `a` 被声明为一维数组 `int a[]`，但在函数体内却使用了二维数组的访问语法 `a[i][j]`。由于一维数组不能进行两次下标访问，导致编译器报错。

**修改方法：**
将 `max` 函数的形参改为二维数组声明，使其与 `main` 函数中传入的二维数组 `int a[10][5]` 匹配。

```c
/* 修改前 */
void max(int a[],int *pmaxstudent,int *pmaxclass) {

/* 修改后 */
void max(int a[][5],int *pmaxstudent,int *pmaxclass) {
```

2. **报错内容：**

```text
[Error] passing argument 1 of 'reset' makes pointer from integer without a cast
[Error] passing argument 1 of 'avg' makes pointer from integer without a cast
```

**错误原因：**
在 `main` 函数中调用 `reset` 和 `avg` 函数时，实参写成了 `b[10]`。`b` 是一个大小为 10 的一维数组（合法下标为 0~9），`b[10]` 不仅发生数组越界，而且它代表的是单个元素（`int` 类型），而函数期望的参数是数组首地址（`int *` 指针类型），因此引发类型不匹配的编译错误。

**修改方法：**
在调用函数时，直接将数组名 `b` 作为实参传入。

```c
/* 修改前 */
reset(b[10],length);
printf("第%d个学生的平均分为%.2f\n",i+1,avg(b[10],length));

/* 修改后 */
reset(b,length);
printf("第%d个学生的平均分为%.2f\n",i+1,avg(b,length));

/* 注意：第二个循环中的 reset 和 avg 调用也需要将 b[10] 改为 b */
```

1. **报错内容：**

```text
[Error] 'x' undeclared (first use in this function)
```

**错误原因：**
在宏定义 `#define SWAP(a, b) {int temp=x;x=y;y=temp}` 中，宏的形参命名为 `a` 和 `b`，但替换体中却错误地使用了未定义的标识符 `x` 和 `y`。当代码在第9行进行宏展开时，编译器在当前作用域中找不到变量 `x` 和 `y` 的声明，从而引发编译错误。

**修改方法：**
将宏替换体中的 `x` 和 `y` 改为宏定义时声明的形参 `a` 和 `b`。

```c
/* 修改前 */
#define SWAP(a, b) {int temp=x;x=y;y=temp}

/* 修改后 */
#define SWAP(a, b) {int temp=a;a=b;b=temp}
```

1. **报错内容：**

```text
[Error] expected ';' before '}' token
```

**错误原因：**
宏定义 `#define SWAP(x, y) {int temp=x;x=y;y=temp}` 中，最后一条语句 `y=temp` 后面漏掉了分号。当在 `main` 函数中调用 `SWAP(a, b);` 时，宏展开变为 `{int temp=a;a=b;b=temp};`，编译器在解析到 `}` 之前没有找到语句结束的分号，因此报错。

**修改方法：**
在宏定义的最后一条语句后加上分号。

```c
/* 修改前 */
#define SWAP(x, y) {int temp=x;x=y;y=temp}

/* 修改后 */
#define SWAP(x, y) {int temp=x;x=y;y=temp;}
```
