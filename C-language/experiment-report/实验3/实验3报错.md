## 3.1报错
这个问题的原因在于 **第11行和第13行代码中的 `putchar("\n");` 使用了双引号**。

### 详细原因解释：
1. **`putchar` 函数的定义**：`putchar()` 函数的参数类型是 `int`（通常用来接收一个字符的 ASCII 码），它的作用是把**单个字符**输出到终端。
2. **单引号与双引号的区别**：
   * `'\n'` （**单引号**）表示一个**字符常量**，在 C 语言中它的类型是 `char`，会自动转换为对应的 ASCII 码（换行符的 ASCII 码是 10）。
   * `"\n"` （**双引号**）表示一个**字符串常量**，它的本质是一个字符数组，传递到函数中会退化为**指针**（即 `char*` 类型，指向这个字符串首字母的内存地址）。
3. **编译器报错信息**：看看你截图底部 Console 里的警告信息：`[Warning] passing argument 1 of 'putchar' makes integer from pointer without a cast`（警告：传递 `putchar` 的第 1 个参数时，将指针转换成了整数而没有进行强制转换）。因为你传了一个字符串指针给 `putchar`，它无法正确识别你想输出的是换行符。

### 解决方法：
将第11行和第13行的双引号改成**单引号**即可：

```c
// 修改前
putchar("\n");

// 修改后
putchar('\n'); 
```
*(或者直接写 `putchar(10);`，因为 `\n` 的 ASCII 码就是 10)*。

### 💡 额外提示（实验1常见的坑）：
你的代码在运行的时候，可能会遇到**程序直接结束，没有等你输入第二个字符**的情况。
这是因为：当你输入第一个字符（比如 `A`）并按下**回车键**时，回车键产生的换行符 `\n` 会留在输入缓冲区中。紧接着 `c2 = getchar();` 会直接读取到这个回车符（`\n`），从而跳过了让你输入第二个字符的过程。

**如果遇到这个问题，可以这样修改输入方式：**
在读取第一个字符后，加一句 `getchar();` 把回车符“吃掉”，再去读取第二个字符。

## 3.3测试报错

输入F，但输出的是一个问号。

出现这个问题的原因在于 **输入时使用了中文输入法（或全角模式），导致输入的字符并非标准的半角英文字母**。

### 详细原因解释：
1. **半角与全角的区别**：
   * **半角 `F`**（纯英文状态）：在计算机中占 **1 个字节**，对应的 ASCII 码是 **70**。
   * **全角 `Ｆ`**（中文输入法全角状态）：在 GBK/GB2312 编码中占 **2 个字节**（例如 `A3` 和 `C6`）。如果你在中文输入法下直接输入了字母，或者是直接打了一个汉字，都属于多字节字符。
2. **`scanf` 的读取机制**：`scanf("%c", &x);` 中的 `%c` 格式控制符，**只会读取 1 个字节**。
3. **为什么输出问号 `?`**：
   当你输入全角 `Ｆ` 时，`scanf` 只拿走了第一个字节（比如十进制的 `-93` 或 `163`），赋值给 `x`。
   此时判断条件 `'A' <= x && x <= 'Z'`（即 `65 <= x <= 90`）是**不成立**的。
   程序走到 `else` 分支，执行 `y = x;`，最后 `printf("%c", y);` 试图打印这个孤立的半个汉字/全角字符的字节。由于控制台无法识别这半个字符，就会显示为乱码或问号 **`?`**。

### 解决方法：
确保在运行程序输入字母时，**输入法处于纯英文、半角状态**（按下 `Shift` 键切换）。

## 3.4测试报错（输入大于100的分数时等级判定错误）

### 详细原因解释：
1. **测试现象**：按照题目要求，当输入数据大于100（例如输入 `105`）时，程序应该提示“输入数据错”。但实际运行这段代码输入 `105` 时，程序输出了 `B`。
2. **代码逻辑漏洞**：
   * 第一个条件 `if (score>=90 && score<=100)` 对 90-100 分设定了严格的上限和下限。
   * 但是，紧接着的 `else if (score>=80)` 只有下限，**没有上限限制**。
   * 因为程序自上而下执行，当输入 `105` 时，第一个条件不满足；但到了 `else if (score>=80)` 时，`105 >= 80` 是成立的，于是程序直接输出了 `B`，跳过了后面的 `else`（输入数据错）分支。
3. **对小于0的拦截**：输入 `-70` 时，最后走到 `else if (score>=0)` 发现不成立，最终进入 `else` 输出“输入数据错”。虽然结果是对的，但逻辑上是依靠“漏网”来实现的。

```c
// 修改前：
    if (score>=90&&score<=100) {
        printf("A");
    } else if (score>=80) {
// ...

// 修改后：
    if (score > 100 || score < 0) {
        printf("输入数据错\n");  // 先处理非法输入
    } else if (score >= 90) {
        printf("A\n");        // 此时不用再写上限，因为>100已经被前面拦截了
    } else if (score >= 80) {
        printf("B\n");
    } else if (score >= 70) {
        printf("C\n");
    } else if (score >= 60) {
        printf("D\n");
    } else {
        printf("E\n");
    }

## 3.4 实验报错与修复详细分析（采用嵌套 switch 方案）

### 一、 原代码存在的问题详细描述

原代码试图通过 `score /= 10` 配合 `switch` 语句来实现成绩的等级划分，但忽略了 C 语言**整数除法截断**的特性以及**边界数据的校验**，导致程序在处理非法数据（越界数据）时出现严重逻辑错误：

1. **大于 100 的正数越界问题（如输入 105）**
   * **现象**：程序输出 `A`。
   * **原因**：输入 `105` 时，执行 `score /= 10` 后，由于整数除法向下取整，结果变成了 `10`。程序进入 `switch` 后，正好匹配到 `case 10:`，从而错误地输出了等级 `A`。
   * **隐患**：输入 `101` 到 `109` 的任何数字，都会被判定为 `A`。

2. **负数越界的潜在漏洞（如输入 -5）**
   * **现象**：程序错误地输出 `E`。
   * **原因**：题目要求小于 0 的数据报错，但如果输入 `-5`，执行 `score /= 10` 后，结果是 `0`。程序进入 `switch` 后，匹配到了 `case 0:`，错误地输出了等级 `E`。
   * **对比**：输入 `-70` 时结果为 `-7`，能正常落入 `default` 报错；但 `-1` 到 `-9` 之间的负数都存在漏判。

3. **输入数据错位**：题目要求非法输入时提示“输入数据错”，原代码的 `default` 中写的是“用户输入错”，未严格扣题。

---

### 二、 修复方案（不使用 if 语句）

为了不使用 `if` 语句，我们采用 **嵌套 `switch`** 的方案进行精确拦截。
* **外层 `switch`**：负责处理十位数（0~10）。
* **内层 `switch`**：针对存在越界可能的 `case 10`（包含100~109）和 `case 0`（包含0~9和-1~-9），在内部套一层 `switch` 进行二次边界校验。

### 三、 完整修复代码

```c
#include <stdio.h>

int main() {
    int score;
    scanf("%d", &score);
    
    // 外层 switch：根据十位数进行分类
    switch (score / 10) {
        case 10:
            // 针对 10 的嵌套：区分刚好100和超过100的情况
            switch (score == 100) {
                case 1: 
                    printf("A\n"); 
                    break;           // 条件成立，score 刚好是 100
                default: 
                    printf("输入数据错\n"); 
                    break;           // 条件不成立，说明 score 大于 100
            }
            break;
        case 9:
            printf("A\n");
            break;
        case 8:
            printf("B\n");
            break;
        case 7:
            printf("C\n");
            break;
        case 6:
            printf("D\n");
            break;
        case 5:
        case 4:
        case 3:
        case 2:
        case 1:
            printf("E\n");
            break;
        case 0:
            // 针对 0 的嵌套：区分 0~9 和 -1~-9 的负数
            switch (score >= 0) {
                case 1: 
                    printf("E\n"); 
                    break;           // 条件成立，score 在 0~9 之间
                default: 
                    printf("输入数据错\n"); 
                    break;           // 条件不成立，说明 score 是负数
            }
            break;
        default:
            // 处理其他负数越界（如 -70 / 10 = -7）
            printf("输入数据错\n"); 
            break;
    }
    
    return 0;
}
```

## 3.4测试报错（switch语句外层缺少default导致负数越界静默退出）

出现这个问题的原因在于 **最外层 `switch` 语句没有编写 `default` 分支，导致极小负数（如 -70）无法匹配任何 `case`，从而直接跳过了整个 `switch` 结构并结束程序**。

### 详细原因解释：
1. **测试现象**：输入 `-70`，程序没有任何输出，直接结束（静默退出）；输入 `-5`，程序能正确输出“输入数据错”。
2. **代码逻辑漏洞**：
   * 代码中定义了 `int tens = score / 10;`。当输入 `-70` 时，`tens = -7`。
   * 进入外层的 `switch (tens)` 后，由于代码中只写了 `case 10` 到 `case 0`，**没有 `case -7`，且最外层也没有 `default:` 分支**。
   * 在 C 语言中，当 `switch` 表达式没有匹配到任何 `case`，并且没有提供 `default` 分支时，程序会直接跳过整个 `switch` 代码块，继续执行后面的代码（在这里直接执行了 `return 0;` 结束程序）。
3. **内层 `switch` 为什么能处理 -5**：当输入 `-5` 时，`tens = 0`，正好匹配到了 `case 0`。进入 `case 0` 后，内层 `switch(score>=0)` 判定为假（`case 0`），输出了“输入数据错”。但 `-10` 及以下的负数（如 `-11`、`-70`）在截断除法后结果小于 `0`，外层直接匹配失败。

### 解决方法：
最严谨的做法是在最外层 `switch` 的末尾补上一个 **`default` 分支**，用来兜底处理所有无法匹配的负数十位（如 `-1` 到 `-9` 即分数 `-10` 到 `-99`，以及更小的负数）。

```c
// 修改前的最外层 switch 结尾：
		case 0:
			switch (score>=0) {
				case 1:
					printf("E");
					break;
				case 0:
					printf("输入数据错");
					break;
			}
			break;
	} // 缺少 default，-70 直接跳到了这里结束

// 修改后的最外层 switch 结尾：
		case 0:
			switch (score>=0) {
				case 1:
					printf("E\n");
					break;
				case 0:
					printf("输入数据错\n");
					break;
			}
			break;
		default:  // <--- 新增这个 default 兜底
			printf("输入数据错\n");
			break;
	}
